# Harmony and Chord Track Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add live read, write, extract and clear tools for the chord track, a tool that turns the chord track into instrument parts, and chord and key information in saved-song reads.

**Architecture:**
- Two new MCP Track Edit task ops, `chords` and `removeChords`, read and remove chord-track events through `context.editor.model.chords.getChordTrack()`.
- `src/harmony.js` writes chords by drawing them as notes in a scratch instrument part, running `Event/Extract to Chord Track`, and removing the scratch track.
- Offline, `src/song.js` names chords from the saved root (circle-of-fifths index) and the 12-slot intervals mask.

**Tech Stack:** Node ESM, `node:test`, zod. Edit-task JS is ES5 (`var`, no arrows) in `device/EditTasks/package/`.

**Spec:** `docs/superpowers/specs/2026-10-07-harmony-design.md`

## Global Constraints

- **Edit-task code is ES5 only** and matches McpTrackOps.js style. It never throws and never calls an unchecked host member: a JS error pops a modal Scripting Error in Studio One, even under try/catch. Use `mtoFn`, return `{ error }`.
- **The chord track is located only through `context.editor.model.chords.getChordTrack()`**, never by name: the name is localized ("Pista de acordes").
- **Chord names in live results** come from `chord.name` as Studio One reports it.
- **Commit trailer** is `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Stage only the task's files (never `.superpowers`), and never push.
- **Tests that read source files** normalise CRLF.
- **`npm test` stays green** (534 pass at start).

## Review Focus

1. **The scratch track must never be left behind.** If writing notes or extracting fails in `live_set_chords`, the scratch track is still removed (`finally`). A removal failure is reported with the track's name. Covered in Task 3 tests.
2. **The user's track selection** is restored after `set`/`extract`/`parts`. Covered in Task 3 tests.
3. **A chord event that starts before the range and runs into it** is removed whole when `replace` is set. The result must warn that its part outside the range was lost. Covered in Task 3 tests.
4. **An empty chord track or none at all** (old device): `live_chords` returns `[]`, or a clear "reinstall the device" error. It must not crash. Covered in Task 1 and Task 3 tests.
5. **Saved songs with no ChordTrack or no KeySignatureMap** give empty arrays, not errors. Covered in Task 2 tests.

**Interfaces:**
- Produces the ops, run through the bridge op `trackTask { ops: [op] }`, whose result is `results[0]`:
  - `{ op: 'chords', from?: seconds, to?: seconds }` → `{ chords: [{ name, start, end }] }`, sorted by start, filtered to events where `end > from && start < to` (missing bounds = unbounded). `start`/`end` are rounded seconds (`mtoSeconds`).
  - `{ op: 'removeChords', from?, to? }` → `{ removed: [{ name, start, end }] }`. It calls `context.functions.removeEvent(ev)` for each event in the range.
  - Both return `{ error: 'the chord track is not available' }` when `context.editor`, `.model`, `.model.chords`, `getChordTrack` or the track's `createIterator` is missing, and `{ error: 'removing chord events is not available' }` when `functions.removeEvent` is missing.

Code to add:

```js
// ---- chord track ----------------------------------------------------------------------
// Seen on 7.2.3: context.editor.model.chords.getChordTrack() is the chord track (its name is
// localized); its events have startTime/endTime and chord.name ("Cm"). The iterator yields them
// newest first. functions.removeEvent(ev) removes one; it shows after the task run.

function mtoChordTrack(context) {
	var ed = context ? context.editor : null;
	var model = ed ? ed.model : null;
	var chords = model ? model.chords : null;
	if (!mtoFn(chords, "getChordTrack")) return null;
	var t = chords.getChordTrack();
	return mtoFn(t, "createIterator") ? t : null;
}

function mtoChordInfo(ev) {
	var c = ev ? ev.chord : null;
	return { name: c && typeof c.name === "string" ? c.name : "", start: mtoSeconds(ev.startTime), end: mtoSeconds(ev.endTime) };
}

function mtoChordsIn(track, op) {
	var from = typeof op.from === "number" ? op.from : null, to = typeof op.to === "number" ? op.to : null;
	var list = mtoEvents(track), out = [];
	for (var i = 0; i < list.length; i++) {
		var info = mtoChordInfo(list[i]);
		if (from !== null && info.end !== null && info.end <= from) continue;
		if (to !== null && info.start !== null && info.start >= to) continue;
		out.push({ ev: list[i], info: info });
	}
	return out;
}

mtoOps.chords = function (context, op) {
	var t = mtoChordTrack(context);
	if (!t) return { error: "the chord track is not available" };
	var hits = mtoChordsIn(t, op), out = [];
	for (var i = 0; i < hits.length; i++) out.push(hits[i].info);
	return { chords: out };
};

mtoOps.removeChords = function (context, op) {
	var t = mtoChordTrack(context);
	if (!t) return { error: "the chord track is not available" };
	var f = context.functions;
	if (!mtoFn(f, "removeEvent")) return { error: "removing chord events is not available" };
	var hits = mtoChordsIn(t, op), removed = [];
	for (var i = 0; i < hits.length; i++) { f.removeEvent(hits[i].ev); removed.push(hits[i].info); }
	return { removed: removed };
};
```

**Interfaces:**
- `NOTE_NAMES = ['C','C#','D','Eb','E','F','F#','G','Ab','A','Bb','B']`
- `fifthsToPitchClass(i) → (i * 7) mod 12`, with negative indices handled: `((i * 7) % 12 + 12) % 12`
- `parseIntervalsMask("FF 0 0 FF 0 0 0 FF 0 0 0 0") → [0, 3, 7]`. A slot counts as present when it is non-zero hex.
- `chordName(rootPc, intervals, bassPc = null) → string`. Match the interval set exactly against this table, keyed by the sorted intervals joined with commas:
  - `0,4,7` → `''`
  - `0,3,7` → `m`
  - `0,3,6` → `dim`
  - `0,4,8` → `aug`
  - `0,2,7` → `sus2`
  - `0,5,7` → `sus4`
  - `0,4,7,9` → `6`
  - `0,3,7,9` → `m6`
  - `0,4,7,10` → `7`
  - `0,4,7,11` → `maj7`
  - `0,3,7,10` → `m7`
  - `0,3,6,10` → `m7b5`
  - `0,3,6,9` → `dim7`
  - `0,2,4,7` → `add9`
  - `0,2,3,7` → `madd9`
  - `0,2,4,7,10` → `9`
  - `0,2,4,7,11` → `maj9`
  - `0,2,3,7,10` → `m9`

  Unknown sets give `NOTE_NAMES[root] + '(' + intervals.join(',') + ')'`. A `bassPc` that differs from the root appends `/` plus the bass name.
- `readSong` adds:
  - `chords: [{ chord, startBeat, lengthBeats, bar }]`. Each ChordEvent's `start` attribute is in beats (absent = 0) and its `length` is in beats. The chord is taken from `Attributes x:id="chord"`: `root` is a fifths index and `intervals` is the mask. Values are sorted by `startBeat`.
  - `keySignatures: [{ root: NOTE_NAMES[fifthsToPitchClass(root)], scale, startBeat }]`. Each comes from a `KeySignatureMap` `<Attributes root scale start>` child: `start` is in beats, and `scale` is the raw string (`''` means not set). An absent map gives `[]`.
- `summarizeSong` adds `chords: ["G @ bar 3", …]` (first 64) and `keySignatures` as given.

The verified sample is `<ChordEvent timeFormat="2" length="4"><Attributes x:id="chord" root="0" intervals="FF 0 0 FF 0 0 0 FF 0 0 0 0" type="1"/></ChordEvent>`, which is Cm at beat 0. Live, the root indices were G=1, D=2 and E=4, so the fifths reading is confirmed.

**Interfaces:**
- Consumes:
  - from Task 1: `trackTask(call, op, opts)` from `src/tracks.js`, which returns the op result and throws on `{ error }` (check `src/tracks.js` for its exact behaviour);
  - `toSeconds` / `manyToSeconds` from `src/time.js`;

  - `parseProgression` from `src/theory/chords.js`;
  - bridge ops `song` (`selectedTracks`, `transport.playing/recording`), `tracks`, `addTrack {type:'instrument'}`, `selectEvents {track}` / `{tracks}` / `{none:true}`, `selectTrack {name, exclusive}`, `command`, `notes {track}` (the `live_notes` shape: `parts[{name,start,end,notes[{note}]}]`).
- Produces:
  - `listChords(call, { from, to }) → { chords: [{ chord, start, end }] }`
  - `setChords(call, { bar, progression, barsPerChord = 1, replace = true }, deps?) → { written, chords, removed, mismatches?, warnings?, undoSteps }`
  - `extractChords(call, { track }) → { track, chords }`
  - `partsFromChords(call, { track }) → { track, parts: [{ name, start, end, notes }] }`
  - `clearChords(call, { from, to }) → { removed }`

`setChords` flow (exact):
1. If `song.transport.playing` or `.recording` is set → `Error('stop playback first')`.
2. `from = await toSeconds(call, \`${bar}.1.1.0\`)`. `progression` is parsed with `parseProgression(progression, { barsPerChord })`. The total beats are the sum of the chord lengths, and `endBar = bar + totalBeats / 4`. This assumes 4/4, the same as `writeChords`. `to = await toSeconds(call, \`${endBar}.1.1.0\`)`.
3. `removed = replace ? (await trackTask(call, { op: 'removeChords', from, to })).removed : []`. A removed event with `start < from - 0.001` or `end > to + 0.001` adds the warning `chord <name> at <start>s extended outside the range and was removed whole`.
4. `before = (await call('tracks', { events: false })).map(t => t.name)`. Then `await call('addTrack', { type: 'instrument' })`. The new name is the name in the new list that was not in `before`; if not exactly one → `Error('could not identify the scratch track')`.
5. `try { await createPart(call, { track: scratch, bar, bars: totalBeats / 4 }); await writeChords(call, { track: scratch, bar, progression, barsPerChord }); const sel = await call('selectEvents', { track: scratch }); const r = await call('command', { category: 'Event', name: 'Extract to Chord Track' }); if (!r.executed) throw new Error('Event/Extract to Chord Track did not run'); } finally { remove the scratch track: await call('selectTrack', { name: scratch, exclusive: true }); const rr = await call('command', { category: 'Song', name: 'Remove Track' }); if (!rr.executed) warnings.push(\`could not remove the scratch track "${scratch}": remove it by hand\`); then restore the selection: selectEvents {none:true}, and re-select song0.selectedTracks (the first one exclusive), each in try/catch }`. Check how `selectEvents` takes a single track: `live_select_events` uses `tracks: [...]`; read the bridge op in BridgeCore and use the right argument shape. A failure inside the finally's removal becomes a warning, never a replacement for the main error.
6. `chords = (await listChords(call, { from, to })).chords`. Then compute `mismatches`: compare position by position with the requested chords. A pair matches when `normalize(read) === normalize(requested)`, where `normalize` maps `maj7`/`M7`/`Δ` to `maj7` and removes spaces. Pairs that differ go in `mismatches: [{ requested, got }]`. A differing count is one mismatch entry `{ requested: N, got: M }`.
7. `undoSteps`: count `removeChords` (1 if anything was removed), `addTrack` 1, the createPart steps (from its result's `undoSteps`), writeChords 1, extract 1, and remove 1. Report the number with the note: "several live_undo steps; easier: live_clear_chords for the range, or call again".

Other flows:
- **`extractChords`:** check stopped; save the selection; `selectEvents {track}`; then `command Event/Extract to Chord Track`.
  - If `!executed` → `Error('nothing to extract from on <track> (no events?)')`.
  - Restore the selection, then return `{ track, chords: (await listChords(call, {})).chords }`.
- **`partsFromChords`:** check stopped; `before = call('notes', {track})`; `selectTrack {name: track, exclusive: true}`; then `command Instrument Parts/Insert Instrument Parts from Chord Track`.
  - If `!executed` → `Error('Studio One could not insert parts on <track> (an instrument track is needed, and chords on the chord track)')`.
  - `after = notes`. The new parts are those whose `start`+`name` key was not in `before`; each is mapped to `{name, start, end, notes: notes.map(n => n.note)}`.
  - Restore the selection.
- **`clearChords`:** convert from/to with `toSeconds` (undefined stays undefined), then `trackTask removeChords`.
- **`listChords`:** convert from/to, call `trackTask chords`, and map `{name,start,end}` → `{chord: name, start, end}`.
